# KD Designer - project guide for Claude

Show controller on an **Arduino Portenta H7** (M7 core, Mbed OS Arduino core), inspired by
Pharos Designer 2: DMX / Art-Net / sACN output, timelines with tracks and effects, triggers,
projectors (PJLink), PCs, UDP/OSC/TCP/HTTP/Modbus, a web UI for programming and a touch panel.
Everything (web UI, project, logs, images) lives on a USB stick. The user (Jaromir) is a show/AV
technician; explain in plain words, he reads the README rather than the code.

`README.md` is the user manual and feature list - read it first for what exists. `NEXT-STEPS.md`
lists known loose ends and the planned tidy-up.

## Rules that are not obvious from the code

- **Things that exist in several places must change together:**
  - **Commands**: firmware `src/Cmd.cpp` (+ `Triggers.cpp` for conditions; device-driver commands in `Drivers.cpp` `*Cmd()`), mock `tools/mock-server.js` (`exec`, `checkCondition`, `drvCommand`), and the UI grammar `GRAMMAR` / `COND_GRAMMAR` in `app-grammar.js` (autocomplete, validation, highlighting, builder, hover help: `matchPart`, `completeBase`, tips, `builderField`).
  - **Effect language**: `data/www/fx.js` and `src/Fx.cpp` - same syntax, opcodes, function numbering, outputs and the integer `rand` hash. `toFixture()` in fx.js = `runEffect()` in Show.cpp = `effectFrame()` in the mock. Firmware only: `prepare()` in Fx.cpp splits the bytecode into a per-frame part (statements and pieces that don't depend on i/u/x/y) and a per-fixture part, and folds operands into instructions; `runEffect` resets only the outputs and inputs per fixture. Run `node tools/fxtest/test.js` after any change to either file. Parameter kinds (number, colour, colour list `#a, #b` = `gradient`, `"text"`, `image`) take 1 / 3 / 1+32 / 2 / 4 slots (`Param::width()`; a colour list's colours are r g b + place, sorted by place: `parseStops` / `fillStops` = `setParam` / `fillStops` in Fx.cpp, same strict number format); `grad` / `txt` / `img` (functions 27-29) get the parameter's slot as a constant first argument and run in `special()` (both files; the 5 x 7 letters are `FONT` = `kFont`). Texts and pictures don't fit a slot: fx.js keeps them in its `DATA` list (slot = index), the firmware in the cue's `FxCue::data` bytes (slot = offset + 1; `setParam` appends, `Program::data` holds the code's default texts) - so `Fx::run` takes the cue's data. Picture values are `img:<w>x<h>x<frames>:<base64 rgb>` (max `MAX_IMAGE` pixels, made by `fxImageFromFile` in app-show.js; `parseImage` = `setParam`'s PImage branch, own base64/UTF-8 code in fx.js so check-project runs it). **Clocks, automation, glide**: `t * <num param>` (either order, exactly two loads) compiles to a hidden slot `t*<name>` (`clockPair` in both compilers, `prog.clocks`; `prepare()` treats it as a frame value) that the player fills per frame: `frame()` in fx.js = `Fx::frameInputs` (t; automation lanes from cue `auto` {name: [[ms, v, curve]]} with `laneValue` / analytic `laneIntegral`, wrap = a looping timeline's length; a live edit's glide `gOff` over `GLIDE` / `kGlide` 0.5 s weighted `(1-k)^2`; clock offsets `cOff` / `cG`). Unchanged it is exactly `t * speed`. `carry()` = `Fx::carry`, used after a live edit (Show.cpp `keepEffects` before / `carryEffects` after `timelineReplaced`; the mock's `timelineReplaced`; the UI previews' `fxPrevRuns`); `startEffect` resets `FxCue::live`. Code without a runner calls `KDFX.atTime` (fills the clocks). UI: automation lane `autoLaneHtml` / `autoClipInner` (`S.tlAuto`, not saved), `autoShifted` / `autoCut` for split, trim and Ableton-style overlap cuts. `tools/fxtest` has `@auto` / `@wrap` / `@edit` cases. **Clip options** (cue `mods`: flip / mirror / repeat / kaleido / invert): `place()` / `invert()` in fx.js = `Fx::place` / `Fx::invert`; the firmware applies `place` once per fixture in `parseTimeline` (FxTarget `i`/`x`/`y`, FxCue `n`), the mock in `effectRun`, the UI previews in `runFxPreview` / the overlay / the clip thumbnails; editor `fxModsHtml`.
  - **Project parsing**: `Show::parse` (ShowParse.cpp) / `State::load` / other `load()`s in the firmware (a new module's `load()` goes in `Project::loadModules`), `normalize()` in app-core.js, and the mock.
  - **Machine Control I/O** (`machineControl` in project.json, points `in0-7 out0-7 io0-11 ai0-2 ao0-3`): firmware `src/Board.cpp` (only built with `-DKD_BOARD_PMC`, env `machine_control`; the default env has no I/O), mock `board*` functions, UI `PMC_*`/`pmc*` in app-core.js, the Machine Control tab in app-drivers.js, the `io` command/condition in the grammar, and the `input` trigger's `io`/`level`.
  - **Project rules** in `model.js` (UI + mock) mirror `ShowParse.cpp`: channel names `dim/intensity/i/master`, `r/red`, `g/green`, `b/blue`, `w/white` (`channelRoles` / `colorSlots`), track fixture order, first-map position (with the map's `square` "round effects": `effectXY` = the `mapPos` loop), fade paths (`EASE` / `ease()` in Show.cpp).
  - **Device history** (Monitoring device view): `Monitor::record` / `flushHistory` / `historyJson` + `Log::search` in the firmware (`/api/history`, `/api/devlog`), `histRecord` / `flushHistory` / `historyLines` / `logSearch` in the mock, `histSegments` / `histGraph` in app-system.js (day-file line format `epoch state kind name`, state `online|offline`, `gone` (left the project on a reload: unknown from there; recorded by each module's `load()` and the mock's `loadProject`), `on|off` projector power, `p:<key>=1|0` show-device reading; `boot`/`alive`, the 600 s alive / 900 s gap rule). Every place that changes a device's online state (or projector power) calls `record`, including the first check; readings are recorded in `setPoint` (Drivers.cpp) / `drvSet` (mock), and which ones count as on/off is `onOff()` = `drvOnOff()`. Log lines match the name/IP as a whole word (`hasWord`).
  - **Touch-panel control state** (`panel <name> text|color|flash|value|enable|disable|reset`, `label`, values sent with `/api/panel?…&value=&vars=name=v;name=v`): `State::setControl` + `statusJson` "labels" and `Web.cpp` `/api/panel` in the firmware, `ctl()` / `/api/panel` in the mock, `panelCtlState` / `panelUpdate` in panel-ui.js. Colours given by actions may be a preset's name (`panel.colors` [{name, color}], `PANEL_PRESETS` default, resolved by `panelColorOf` in panel-ui.js only; the editor's swatches are `presetSwatches` in app-system.js). Page switching (`panel <panel|all> page <page|start>`): `State::panelGo` (status `panelGo` {page, n} per panel name, n never reset) = the mock's `panelGo`; the panel follows it in `followGo` (panel.html, ignores what was there on its first status); grammar `{pnl}` / `{ppage}`. Renaming a panel / page / control (`data-orig` on the name field, `onBound` in app-core.js) runs `renamePanelRefs` (app-system.js): a new command that names a panel, page or control goes there too. A panel's header shows only the mode groups in the panel's `modes` (none = none; `renameModeRefs` keeps them). A panel's **shared part** is a page with `shared: true` (`sharedAt` '' | bottom | left | right `PANEL_SHARED_AT`, `sharedWidth`, its `bg` colours only the band; pages' `noShared`): `panelPagesOf` leaves it out (so start / go-to lists, grammar and panel.html navigation never see it), `panelSharedOf` finds it; panel.html draws it in `#sharedTop` / `#sharedBot` with its own handlers (`wire(root, getPg)`, `updateAll()`); the editor lists it as ★ and draws it faded (`.panel-ghost`) around the page preview. Firmware and mock see it as just another page with controls. Variable links (`var`, `links.r/g/b/h/s/v/x/y`, `rgbScale`) are worked out by the panel only (`panelLinkValues` out, `panelLinkedValue` back). Control types are UI-only (the firmware and mock know a control by name and keep its value as text): `radio` (`options` "A, B, C", value = the choice's text), `led` (`panelLit`, `is`), `number`, `image` (file in `show/media`), slider `look`/`mid`; a page's `grid` (1-4 small cells per normal cell: `panelFine` / `panelSetFine` rescales its controls, sizes and places count in small cells, `panelSize` gives the defaults), a page's `bg` and a panel's `sleep` ("go black after", seconds) live in panel.html. Panel triggers get `{value}` (and `{r} {g} {b}` for `#rrggbb`, `{x} {y}` for `x,y`) in `Triggers::panelEvent` and the mock.
  - **Device groups** (`deviceGroups`, `kind` = pc | projector | tcp | a show-device type; none = network): `State::groupMembers` / `forMembers` used by `pc`, `projector`, `send tcp` in Cmd.cpp and `Drivers::command`; mock `kindGroup` / `forMembers`; UI `groupsSection` (app-system.js) and `kindGroups` / `findKindGroup` in app-grammar.js. A real device name wins over a group of the same name.
  - **`… interval <s>` and lists** (`pc all wake interval 1`, `kissbox io 1.all on interval 0.5`, `knx gw write a,b on`): `spread` / `targets` + the `delayed` queue run by `Cmd::poll()` (main loop) and `cancel intervals` in Cmd.cpp, `Drivers::split` (Kiss-Box `<slot>.all` / `all` from `kissCh`, KNX addresses, NETIO outputs; text forms like `send` keep "interval" as text); mock `spread` / `drvSplit` / `delayedSteps`; UI `splitInterval` / `completeInterval` / `LIST_PARTS` in app-grammar.js; `intervalSteps` (app-grammar.js) is the UI copy of the step order for the editor strip (`intervalStripHtml` / `ivlPlay`), the list tag (`ivlTag`) and the flow (`cmdOutputs` `at`, the ⏱ `seq` node, `ats` in `flowPlay`): keep it in step with `spread`. `/api/status` `intervals` (`Cmd::statusJson` = the mock's status) lists a trigger's waiting steps; `updateTrigRunning` keeps its row lit. Without an interval only lists are split (a group alone still goes through `forMembers`).
  - **Show files** (`.kdshow` = `{ kdshow: 1, exported, project, media: { name: base64 } }`, media = map backgrounds and touch-panel `image` controls: `showMediaNames` in app-system.js = `mediaNames` in launcher.js): `exportShow` / `openShow` in app-system.js and `readKdshow` / `ctlKdshow` / `import` in tools/launcher.js. The launcher finds controllers by the ArtPollReply short name "KD Designer" (`sendPollReply` in Net.cpp) and reads `/api/status` `version`/`project`/`update.target`.
  - **Network setting** (`network`: `dhcp ip mask gateway dns dns2`): checks `fixedProblem` (Net.cpp) = `netProblems` (model.js, used by Settings and `save()`); what is in use = `Net::statusJson` (`/api/status` `net`) = `mockNet`. Network test: `Net::requestTry/confirm/takeRevert` + the trial in `Net::maintain` (main loop switches), `NetSafe` (marker file, rewrites only the `network` value of project.json by scanning the text, boot check incl. `network-reset.txt`, `idle()` on the web thread so it never races a save), `/api/network/try|confirm` (confirm has CORS: the old page knocks on the new address); mock `netTrial` (`KD_NET_TRIAL_MS` env shortens it and makes the PC mock offer the test); UI `netTrialOffer` / `netTrialDialog` / `netTrialSeen` (any editor that sees a running test in the status confirms it) in app-system.js.
  - **Mode groups** (`modes`: `startup`, `var`, `stateInfo` per state with `enter`/`leave`/`color`/`icon`; trigger `onlyIn`): `State.cpp` (power-up state, `previous`, `since`, history `mode:<group>` / `m:<state>`), `Triggers::changeMode` (leave, enter, mode triggers, variable) with the enter/leave actions as hidden Manual triggers from id 20001, `onVariable` (variable -> mode), the `onlyIn` check in `runTrigger`; the mock's `changeMode` / `modeLoad` / `stepState` / `trigById`; the Modes page and `modeProblems` in app-system.js, `onlyInField` in app-triggers.js, the panel header in panel.html.
  - **Clock maths**: `src/Clock.cpp` (days, summer time, sunrise/sunset, calendar periods with weekdays `days`, no `from` = all year) = `days` / `inPeriod` / `periodOn` / `sunUtc` in `model.js` (used by `Sched` and the Schedule page in app-system.js and `SchedM` in the mock).
  - **Dates**: the UI shows/types DD-MM / DD-MM-YYYY (`dateShow` / `dateStore` in model.js, `euDate` / `euStamp` in app-core.js); calendar periods stay stored MM-DD / YYYY-MM-DD. `date between` conditions are typed DD-MM when `settings.dateOrder` is `"dmy"` (`parseDate(…, dmy)` in Clock.cpp, `SchedM.condDate` in the mock); `normalize()` rewrites older projects' conditions once and sets it.
  - **Trigger Test** (`/api/trigger?id=&test=1`): `Triggers::test` + the `tracing()` / `note` lines in `runTrigger` / `runActions` (Triggers.cpp) = the mock's `trace` in `runTrigger` / `runActions`; UI `trigTest` / `trigTestHtml` in app-triggers.js. Line kinds `c` / `a` / `n`; only the fired trigger's own run (depth 0 / 1). A new early return in `runTrigger` gets a trace note.
  - **Locate** (`locate <ids> [for <s>]` / `locate off`): `Show::locate` (ShowParse.cpp: needs `colorSlots`) sets `locMask` / `locUntil`, applied last in `Show::tick` (over GM and blackout) = the mock's `locate()` + `loc` in `tick`; grammar `{fixlist}`; UI `locateFixtures` (app-rig.js).
  - **Network switches** (type `netgear` in project.json, shown as "Network switch", command word `switch` with `netgear` kept as the older word: `cmdType` in Drivers.cpp = `drvWord` in the mock; any SNMP v2c switch, read-only: `snmpCall` / `snmpWalk` / `pollNetgear` in Drivers.cpp, run in the HTTP thread, replies under 1024 bytes so a cut-off reply is asked again with fewer rows): the port check `netgearCompare` (Drivers.cpp) = `netgearPoll` in the mock (same issue texts, points `p<n>` / `changes` / `changed`, status `ports` `{n i a up sp mac m l poe x}`); what Remember / Watch stores is `ngExpect` in app-drivers.js (`expect` per port number, `names`). Only remembered ports are on/off readings for the history (`onOff` = `drvOnOff`). Without a switch, the SNMP code can be tried on a Mac against `/usr/sbin/snmpd -f -C -c <conf> udp:127.0.0.1:1161` (conf: `rocommunity public 127.0.0.1`) by compiling that part of Drivers.cpp with small String / EthernetUDP / millis shims.
  - **Backups** (`show/backups/YYYY-MM-DD_HH-MM-SS.json`, newest `KD_BACKUPS`): `Storage::keepBackup` (a rename in `handleProjectPut`, falls back to `.bak`), `/api/backups`, the boot fallback in main.cpp = the mock's `keepBackup` / `/api/backups`; UI `loadBackupList` / `restoreBackup` (app-system.js, restore = `replaceProject`, keeps `network`).
  - **Media uploads and stick space**: every upload goes through `mediaUpload` (app-core.js: progress bar over 150 KB, 15 min limit); `handleMediaPut` (Web.cpp) writes 8 KB pieces unbuffered from a heap buffer (~175 KB/s on the board; `txBuf` is only 8 segments = 4288 bytes, the MSS is 536: writing 8 KB into it hung the board). Testing uploads over 1 MB with curl needs `-H "Expect:"` (curl's 100-continue wait got no answer and stalled) and `--noproxy '*'`. `/api/status` `stick` `{total, free}` KB = `Storage::spaceJson` (read by the save thread in `measureSpace`, asked again with `Storage::spaceChanged()` after an upload / delete / mount; never on a status request: a stick without a kept free count gets its whole FAT walked) = the mock's `stickSpace`; UI `stickText` / `stickInfoHtml` (app-system.js).
- **Timeline triggers** (`type: "timeline"`, `on` start | end | release (default) | pause | resume, `timeline` 0 = any; old `timeline_end` = on end, converted by `normalize()`): the engine queues `Show::TlEvent`s (`tlEvents` in Show.cpp: `startTimeline`, end in `updateTimeline` (which also releases a timeline with `"end": "release"`, fade `endFade` ms; none = hold, older projects), `releasePlayback` once per release with a reason, `pauseTimeline`; cleared by `stopAllPlaybacks` so a reload fires nothing), the main loop hands only the already-queued ones to `Triggers::onTimelineEvent` (`kTlOn`). Mock: `tlEvent` (flushed with `setImmediate`). UI: `TIMELINE_ON` / `tlOn` (app-core.js), `TL_WHY` / `TL_CAUSE` and `cmdEffects`' `act` for the flow, setsOff and loops (app-triggers.js).
- **Where used** (`whereUsed` in app-main.js) reads trigger lines with `lineRefs` (the grammar's `classify`, which returns the matched `part` per word): a new placeholder that names a scene, timeline, variable or device must be added to `USE_KINDS`, and a new project field that refers to one (panel control link, trigger setting) to `whereUsed`. Renames follow the same way: `renameNameRefs` (app-main.js, called from `onBound` *before* the new name is written, because the grammar only recognises the old name while the item has it) with `RENAME_PARTS` / `GROUP_PARTS` - add a new placeholder or name field there too. The `?` list (`SHORTCUTS` in app-main.js) must follow the `views.<page>.keys` handlers.
- **Timeline clip length** (`len`/`out` on a cue): the firmware turns it into a release cue (`pushCue` in ShowParse.cpp, `release`/`from` in `Cue`) and fades the track's opacity (`TrackFade.op`, `endRelease` in Show.cpp); the mock mirrors it (`timelineEvents`, `endRelease`). No `len` = hold until the next cue (old projects). - **Threads**: anything touching the engine holds `g_engine` (rtos::Mutex). Events (timeline end, trigger cues, device state, variables) are queued and handled in the main loop. - **Memory budget** (20 Nov 2026): RAM ~30 %, flash ~39.5 % = 708 KB (Machine Control build ~31 % / ~42 % = 747 KB, firmware.bin 786 KB; full newlib since 9 Nov 2026 costs ~35 KB). Flash is the whole 1.75 MB after the bootloader since 10 Nov 2026 (`flash_layout = 100_0` + `board_upload.maximum_size`, `kAppEnd` 0x08200000 in Update.cpp; the M4 is not used). Firmware 0.2.0 and older accept network updates up to 768 KB (786,432 bytes) of firmware.bin only, so the first update to such a board must stay below that: the Machine Control build is ~19 KB over it (20 Nov 2026) (check `.pio/build/machine_control/firmware.bin`), so such a board goes over USB once. With `KD_MAX_UNIVERSES` 8 (~20 KB RAM per universe). Three places:
  - **Heap** (~375 KB, internal RAM): ~196 KB used with an empty show (thread stacks, network, USB), ~100 KB free with the feature demo. Every connection, String and small JSON lives here; blocks up to 256 bytes come from a 48 KB pool inside it (`HeapPool.h`; its free bytes are added to the free-heap figure). The trigger table is not here (SDRAM).
  - **D2 SRAM** (`src/D2Ram.*`, 256 KB at 0x30000000): playback buffers `pbs` (~140 KB, `D2Ram::array`) and the log ring (~68 KB, `D2Ram::keep`: not cleared on reset, so the log, the start reason and the breadcrumbs `Log::crumb` survive a watchdog/crash restart).
  - **SDRAM** (8 MB, `src/BigRam.*`): the project text and JSON (`JsonDocument(BigRam::json())`), the engine tables (`BigRam::Vec<T>`: fixtures, scenes, timelines, cues, effects), the trigger table (its action lines point into the project JSON), the receive queue (`NetRx`), and big replies (`BigRam::Text` for status/log). **Never hand SDRAM memory to the network or other DMA**: data sent straight from SDRAM arrived garbled; `writeAll` in Web.cpp copies it to internal RAM first. Thread stacks stay in internal RAM for that reason.
- **Arduino core fixes** (found on the first hardware run, 6 Nov 2026): `tools/core/variants/PORTENTA_H7_M7` is the core's variant with a `libmbed.a` rebuilt for 48 lwIP sockets, 32 of them TCP (Arduino's has 4; `board_build.variants_dir`; rebuild in WSL per `tools/core/README.md`; `lwip.mem-size` can't grow, it has a fixed 16 KB slot). `lib/SocketWrapper` is Arduino's with the `readSocket` busy-loop fixed, a non-blocking `write()` and a time limit on `connect()` (see `lib/README.md`). - **Speed traps found by the stress test (9 Nov 2026, `tools/stress/`, results in README "Capacity (measured)")**, don't undo:
  - `platformio.ini` `build_unflags = -mfloat-abi=soft --specs=nano.specs`: PlatformIO's builder forced software floating point and newlib-nano. Check `.f64` instructions in a disassembly if maths gets slow again.
  - **Saving**: `handleProjectPut` answers once the project is loaded and hands the text to `Storage::saveProject` (thread "save": tmp file, backup, swap; `/api/status` `save` = `{seq, written, busy, ms, failed, error}`, the PUT reply has `seq`). While it writes, GET `/api/project` serves the text from memory (`Storage::latestProject`); `reload` (Cmd.cpp), `NetSafe::idle` and the update restart wait for it (`waitProject` / `projectBusy`). Mock: `saveSt`, env `KD_SAVE_LOAD_MS` / `KD_SAVE_WRITE_MS` / `KD_SAVE_FAIL`. UI: `xhrSend` (upload progress), `progress()` bar, `apiProgress` for loading, the "writing to the stick…" / "not on the stick!" chip in `updateHeader`. The writer uses 32 KB pieces from D2 SRAM (64 sectors = one USB command in `lib/Arduino_USBHostMbed5`), others `Storage::writeFile`'s 8 KB, unbuffered (`setvbuf _IONBF`). The log line "Project saved (… [json …, fixtures …, triggers …])" has the time per load step (`Project::timePart`). Receiving: `MbedClient::read` (lib/SocketWrapper) takes data straight from the socket past its 256-byte ring. Parsing: `lib/ArduinoJson` moves found strings to the front of `StringPool` (keys every object has were at the back: 3x slower).
  - **Web server waiting list** (`Waiting` / `takeHead` / `httpLoop` in Web.cpp): every new connection is accepted at once and served only when its whole request header is in (POSTs first, then oldest; one request per round). Reading requests in turn with a 2 s wait each let a browser's unused spare connections hold everyone up, and with ~7 queued lwIP reset new ones (black page). Limits `KD_HTTP_WAITING` / `KD_HTTP_HEAD_MS` / `KD_MAX_SSE` (Config.h); `stats.httpRefused`; `/api/threads` = stack use per thread (each open connection has a `readSocket` thread, 1.5 KB stack in lib/SocketWrapper). Test with `tools/stress`-style scripts: idle sockets + parallel page loads + several `/api/events`.
  - **Never wait for a worker thread under `g_engine`**: a TCP/Modbus connect to a device that is off takes ~18 s (lwIP ignores the socket timeout), so `Io::load` hands new device lists to the io thread (`nextTcps` / `haveNext`) instead of locking its lists - it waited under `g_engine` and the watchdog restarted the board on a save.
  - **Reading files line by line**: use `Storage::Reader` (8 KB stdio buffer = one USB command; stdio's own 1 KB made `Log::search` on 5 × 8 MB log files take seconds). `Log::search` skips log files outside the window (first line of each), matches in place and keeps hits in SDRAM; `/api/history` and `/api/devlog` reply from `BigRam::Text`. The Monitoring device view asks for the history first, then the log, and refreshes only new log lines (`monDetailLoad`, `S.mdCache`).
  - **Faders**: udp/osc triggers with `latest` run at most every `KD_LATEST_MS` with the newest value (`fireNetwork` / `runHeld` in Triggers.cpp, UI `latestField` in app-triggers.js); the mock has no UDP input, so nothing to mirror there.
  - **Data cache**: Mbed's H7 Ethernet driver switches it off at start; `cacheOn()` in Net.cpp switches it on again (write-through `FORCEWT`, MPU region 4 = Ethernet `Rx_Buff` uncached, rechecked every second in `maintain`). SDRAM is write-back cached (`BigRam.cpp`, MPU region 5). So **nothing may hand cached memory to DMA**: network sends from SDRAM go through `writeAll`'s bounce buffer, big stick reads/writes through 512-byte buffers (`Storage.cpp`). The USB stick, DMX UART, QSPI and Machine Control I/O are CPU-driven.
  - **Heap**: `src/Heap.cpp` replaces Mbed's malloc wrappers (needs the weakened symbols in `libmbed.a`, see `tools/core/README.md`) and serves small blocks from `HeapPool.h` (malloc+free 0.43 µs instead of 2.8: newlib's lock is an RTOS mutex). The pool must stay a zero-initialised global without a constructor (malloc runs before global constructors). Still keep allocations out of per-packet / per-fixture / per-frame paths. `String::equalsIgnoreCase("literal")` and `substring()` allocate: compare with `strcasecmp` / `strncmp` in place. Don't make newlib's heap lock a critical section (tried: the board hung at boot, no USB; recovery = bootloader + dfu-util, see HARDWARE-TEST-PLAN).
  - Engine tables keep no Arduino Strings per fixture (`Slot::name` points into the project JSON), and project loading looks fixtures up by id index (`fixIdx` in ShowParse.cpp), never by searching the list.
  - The stick's log is written by its own thread (`Log::startWriter`, BelowNormal); UDP/OSC trigger messages get `KD_UDP_BUDGET_US` per main-loop round, bursts (`repeat <n> times` without every) `KD_BURST_BUDGET_US`. Hundreds of log lines a second still slowed everything (stick writes): at most `KD_TRIGGER_LOG_PER_S` "fired" lines per trigger per second.
  - The firmware is built with `-Os`: hot functions are `KD_FAST` (`optimize("O2")`, Show.cpp / Fx.cpp) and their helpers `KD_HOT` / `always_inline` (`testBit`, `roundInt` = lroundf as one VCVTA instruction): with `-Os` even `testBit` was a function call per channel. GCC won't inline across different optimize attributes, so a helper used by a `KD_FAST` function needs one of the two. Not file-wide: that cost ~25 KB flash.
  - `LOGD`/`LOGI`… check the level before evaluating their arguments (`KD_LOG` in Log.h). `Cmd::tokenize` makes one String per word (`substring`, vector reserved; adding a character at a time re-allocated each one). `Vars::set` reserves 8 (a growing `std::vector<String…>` copies every String: Arduino's move isn't noexcept).
  - `/api/status` `stats.tickParts` (µs per frame: fx, fade, mix, out), `trigUs`, `busyUs`, `udpDropped`: look there first when something gets slow.
  - The PC stress tool must pace evenly (`pace` in stress.js): Windows timers made bursts of ~50 packets, and the Ethernet chip holds ~7 back-to-back packets.
- Keep C++14 (no `if` with initializers, no structured bindings); `bit` is an Arduino macro (use `testBit`); chrono literals need `using namespace std::chrono_literals`.

## Style

- Comments explain *why*; match the surrounding density. UI text and README in plain English, short.
- Vanilla JS: `$`/`$$` helpers, `render()` rebuilds the current view from `views[S.view]()` and runs `views[S.view].after()`; data binding through `data-p="path"` (+ `data-t` type, `data-r` re-render on change); state in `S`; project via `P()`; `markDirty()` after edits.
- Page keyboard shortcuts go in `views.<page>.keys = (e) => …` (one global handler calls it when not typing; Ctrl+S is global). Animations/polls use `pageAnimation(name, frame)` / `pagePoll(name, fn, ms)` so `render()` stops them. Links to another item use `data-goto-trigger|timeline|effect="<id>"` (handled globally, no per-page wiring).
- The UI files share one global scope: code that runs at load time may only use what earlier files define; everything else is called later and can live in any file.
